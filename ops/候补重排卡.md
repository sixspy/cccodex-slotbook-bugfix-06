# 候补重排卡（BUGFIX-06）

> 本卡一经选定当天封口，禁止改口。取消候补必须连带重排名次。

## 一、口径选定：甲路径 `same_tx`（唯一）

| 项 | 选定 |
|----|------|
| 正确性口径 | **甲：持档锁后同事务改「已取消」并重算后续名次写入名次册** |
| 未选 | 乙：先落重排影子草稿再原子改取消与名次 |
| 禁止 | 两条口径混用；只从列表删行 |
| 路径标识 | `path = "same_tx"`，写入取消回执与审计 |

甲路径执行序（单事务，任一步失败则取消与名次同滚，两边零改）：

1. 读候补行，校验 `status='候补中'`。
2. 取该候补所属档期的档锁 `slot:<code>`；抢不到 → `409`，只留争用痕（`contention_log`），业务零写。
3. 同事务内：`UPDATE waitlist SET status='已取消'`。
4. 同事务内：对**同档期同队列**（`slot_id` 相同、`status='候补中'`，按 `id` 升序）重算连续名次，
   写入名次册 `waitlist_rank`（见 §二）。
5. 写审计 `waitlist_cancel`，payload 含 `path`、`reranked_from`、`reranked_count`。
6. 提交成功后释放档锁。任何一步抛错 → 事务回滚，取消与名次都不落。

## 二、名次册（rank ledger）

- 新增表 `waitlist_rank(wait_id PK, slot_id, queue_rank, promotable, updated_at)`。
- 名次是**落库**的账，不再是列表渲染时按行号临时算出来的（原实现是假绿，取消后空洞）。
- `queue_rank`：同档期内 `候补中` 行按 `id` 升序的连续 1..N。
- `promotable`：标记该档队列头名（`queue_rank=1`）为「可晋升头」，同档唯一。
  是否真有足够空位仍由晋升写口在持档锁后重验（不放宽既有容量校验）。

## 三、同态五处（必须一致）

| # | 面 | 同态要求 |
|---|----|----------|
| 1 | 候补页 | 显示 `queue_rank` 与「可晋升头」标记，取消后立即递补 |
| 2 | 名次列 | `/api/waitlist` 的 `queue_rank` 取自名次册 |
| 3 | 可晋升头 | `promotable` 与名次册一致，晋升须验头名 |
| 4 | 对账页 | `/api/reconcile/{code}` 校验同档候补名次连续、无空洞（`waitlist_rank_ok` 取真值） |
| 5 | 审计页 | `/api/audit` 出现 `waitlist_cancel` 且带 `path`/`reranked_count` |

## 四、假绿夹具与双红

- 夹具 `tests/test_waitlist_rerank.py::false_green_queue`：取消回执成功、状态已改、名次不动。
- 失败测①`test_cancel_success_must_rerank_following_waiters`：验后到者递补。
- 失败测②`test_two_people_cancel_adjacent_must_contend_slot_lock`：验相邻取消抢档锁、后到零写。
- 双红齐后才准改 `waitlist_svc` / `hold_svc` / `reconcile_svc` / `audit_svc` 与候补页。
- 偏航处置：若实现偏离本卡口径 → 记「候补重排偏航」并拒写，不得降级为只改状态或只删行。

## 五、验收

- 双红转绿；原冒烟/空桩 6 测不回退。
- 取消必重排：`reranked=True`、`path="same_tx"`。
- 相邻并发取消：后到 `409` + 争用痕，业务零写。
- 五处同态。
